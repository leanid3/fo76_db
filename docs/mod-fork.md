# Форк Invent-O-Matic Stash под fo76db

Документ для Claude Code в двух репозиториях: **fo76db** (`~/src/fo76db`, приложение) и **форк мода** (`~/src/Invent-O-Matic-Stash-modificaed`, ActionScript 3, лицензия GPL-3). Здесь записано, чего не хватает оригинальному моду для цепочки разбора легендарок по персонажам, и как делится работа.

Версия оригинала: `Version.VERSION = 2.85`, под игру 1.7.26.13. Мод грузится из `Data/InventOmaticStash-UO.ba2` (внутри swf), конфиг — `Data/inventOmaticStashConfig.json`, список легендарных модов — `Data/LegendaryMods.ini`.

## Что проверено в игре и в коде (почему нужен форк)

| Что | Факт | Где |
|---|---|---|
| Правило scrap сопоставляет `excluded` только с **названием** предмета (`item.text`) | В названии виден лишь эффект ★1, эффекты ★2–★4 не видны. Переименованные предметы (`1. left_arm ¢`) не совпадают ни с чем | `ItemWorker.as: shouldScrap` (~315–385) |
| Защита `protectionConfig.scrapProtection` на правила scrap **не действует** | Проверено тестовым прогоном `testRun` на Skrom_TV: V63-BERTHA, The Debilitator, Whacker Smacker и другие из `itemNames` попали в очередь разбора. Защита нужна лишь для блокировки предмета в интерфейсе | `ItemProtection.isProtected` вызывается только из `InventOmaticStash.as` (~326) и `ItemWorker.as` (~2041), но не из `scrapItems` |
| Эффекты по звёздам мод умеет читать у правил **transfer**, не у scrap | `checkLegendaryEffects` + `legendaryEffects` + `legendaryEffectsMatchMode` (`ItemWorker.isItemMatchingLegendaryConfig`, ~905–1040) используют `ItemCardData` и `LegendaryMods.getLegendaryModName(desc, star)` | `ItemWorker.as`, `utils/LegendaryMods.as` |
| Учёт звезды при сопоставлении эффекта | Нет: список — просто имена («Intelligence» бывает на ★2 и ★3, «Durability» тоже) | `legendaryEffects` — массив строк |
| Привязка правила к персонажу и аккаунту | Есть: `checkCharacterName`/`characterName`, `checkAccountName`/`accountName` (`ItemWorker.isTheSameCharacterName`) | работает у scrap и у transfer |
| Клавиши numpad | Уже работают: `"N0"`…`"N9"` в `hotkey` (`Buttons.KEYBINDS`, ключи в нижнем регистре: `n1` = 97). Новых кнопок в моде делать не нужно | `utils/Buttons.as` |
| Тестовый режим | `testRun` в правиле: показывает очередь (`[INFO] "N items queued: …"`), ничего не делает | `ItemWorker.as` (~1339, ~1369) |
| `LegendaryMods.ini` | Файл пишет сам мод (`characterInventories → <имя персонажа> → legendaryMods[]` с `name`, `stars`, `isLearned`, `isKept`). **Аккаунта в файле нет**, а имя «main» бывает у нескольких аккаунтов | `utils/LegendaryMods.as` |

## Чего не хватает моду (задачи для форка)

Порядок — по важности. Для каждой задачи условие «готово» — прогон `testRun` в игре.

1. **Эффекты по звёздам в правиле scrap.** Дать scrap-правилу те же поля, что у transfer: `checkLegendaryEffects`, `legendaryEffects`, `legendaryEffectsMatchMode`. Элементы списка — строка (любая звезда) либо объект `{"name": "Aegis", "stars": 4}`. Сопоставление по названию эффекта из карточки предмета, **не** по названию предмета. Условие готовности: предмет «Chameleon Ultracite Right Leg» (Chameleon ★1, Glutton ★2, Electrified ★3, Aegis ★4) не попадает в очередь у Skrom_TV, если в списке исключений `{"name": "Aegis", "stars": 4}`, даже если предмет переименован.
2. **Защита действует на scrap и transfer.** Вызывать `ItemProtection.isProtected` перед постановкой предмета в очередь разбора и передачи (переключатель `respectProtection`, по умолчанию `true` для новых правил). Причина защиты пишется в лог и в вывод `testRun` (`Named`, `Favorite`, `Known Legendary Mod`, …). Условие готовности: V63-BERTHA из `scrapProtection.itemNames` не попадает в очередь разбора.
3. **Годролл как условие «И».** Новое поле защиты, например `protectionConfig.godrolls: [{scope: "weapon"|"armor", slots: [[...], [...], [...]]}]` или `godrollProtection`. Предмет защищён, если у него ≥3★ и эффекты ★1, ★2, ★3 принадлежат соответствующим спискам `slots[0..2]`; ★4 не в счёт. Поведение и «хорошие» эффекты — как в `fo76db/rolls.py` и `fo76db/legscrap.py` (`GOOD`, `grade`). Условие готовности: предмет с 3 «хорошими» звёздами защищён, с 2 — нет.
4. **Решение «кому достаётся предмет» внутри мода.** Сейчас приложение пересчитывает и переписывает все правила в `inventOmaticStashConfig.json` после каждой выгрузки. Предлагается файл плана `Data/inventOmaticPlan.json`, который мод читает при старте (как `LegendaryMods.ini`, `URLLoader`):
   ```json
   {
     "version": 1,
     "characters": [{"account": "leanid3", "name": "leanid2", "priority": 0}],
     "learned": {"leanid3/leanid2": [{"name": "Aegis", "stars": 4}]},
     "protected": {"names": ["V63-BERTHA"], "godrolls": []}
   }
   ```
   Для каждого предмета: для каждой звезды найти персонажей, не выучивших эффект; назначенный — с наименьшим `priority` (при равенстве — по порядку списка). Предмет принадлежит назначенному персонажу самой приоритетной невыученной звезды (правило «выше приоритет — первым»). Решение для текущего персонажа: `keep` (нужен другому — не разбирать, передать), `scrap` (назначен мне: разобрать и выучить, либо выучено всеми), `protected`. Новый режим правила scrap: `"mode": "chain"`. В `testRun` выводить причину по каждому предмету («оставить: нужен Skrom_TV — Aegis ★4»).
5. **Правило transfer по цепочке** (опционально): `"mode": "chain-give"` (передать в контейнер предметы, назначенные другому) и `"mode": "chain-take"` (забрать из контейнера назначенные мне). Клавиши — numpad (`n1`, `n2`, …). Так закрывается «выкидывать/передавать по персонажам».
6. **Аккаунт в `LegendaryMods.ini`.** Писать рядом с именем персонажа `accountName` (из `ContainerName`/`AccountName` в `ItemWorker`), чтобы приложению не приходилось брать аккаунт из `itemsmod.ini` (сейчас так, см. `importers/inventory.py: _accounts_beside`). Формат остаётся обратно совместимым: старые читатели пропускают незнакомые поля.
7. **Идентификатор формата.** В корне конфига — `"modFork": {"name": "fo76db", "version": 1}` и/или строка в `Version.as`/логе мода, чтобы приложение отличало форк от оригинала и не генерировало новые поля для старой версии мода.
8. **Сборка и выпуск.** В репозитории форка есть только `.as` (`.swf` в `.gitignore`), инструкции сборки нет. Нужны: `BUILD.md` (компилятор, команда, упаковка swf в `InventOmaticStash-UO.ba2`, путь в `Data/`), номер версии в `Version.as`, список изменений относительно оригинала, сохранение уведомления об авторах (GPL-3).

## Что делает приложение (fo76db) при переходе

1. Определить версию мода: `modFork.version` в конфиге (или строка в логе). Нет — работать как раньше (правила по названиям, `excluded`).
2. Генерация правил (`fo76db/legscrap.py: build_rules`) при версии ≥ 1: `legendaryEffects` с учётом звёзд вместо списка названий, `respectProtection`, без дублирования защищённых названий в `excluded`. Старый путь остаётся запасным.
3. Писать `Data/inventOmaticPlan.json` (приоритеты, выученные моды, защита) — только по явной кнопке, с бэкапом и сохранением inode, как `iomconfig.save`. Расположение: рядом с конфигом (`/games/fallout76configs/modconfig/` → `Data/`), копия в `_backup_<ГГГГММДД>/`.
4. Страница `/protected`: показать версию мода, блок «Годролы» (формат `slots`), предпросмотр решения по предмету (причина «оставить/разобрать/защита»).
5. Развернуть собранный `.ba2` вместо оригинала: **единственная запись в игру помимо конфига**, поэтому только по явному подтверждению пользователя, с бэкапом оригинала. Порядок в `sResourceArchive2List` не менять (см. `docs/mods.md` в `/games/fallout76configs`).
6. Тесты (`tests/test_legscrap.py`) и документация (`CHANGELOG.md`, `docs/user-guide.md`, `docs/architecture.md`, `docs/data.md`, `docs/iom-editor.md`) — по правилам `CLAUDE.md`.

## Что уже сделано в приложении (без форка)

- Приоритет персонажей: `profiles.priority` (0 — высший), редактируется в «Настройки → Персонажи».
- Цепочка по выученным модам: `fo76db/legscrap.py` (`Chain`), советы `leg_give`/`leg_self`/`leg_learned` на «Вес».
- Правила LegeScrap по персонажам (`/protected`, «Записать в конфиг игры»): исключения по названиям эффектов + названиям защищённых предметов (обход задач 1–2: работает только для эффектов ★1 в названии и только для неизменённых названий).
- Список защиты `protected_items`: 120 уникальных предметов и годролы (стартовый набор «хороших» эффектов).
- Уведомления «годролл без защиты» (Telegram, ntfy).

Все названия и «хорошие» эффекты хранятся в БД приложения, не в моде.

## Известные ограничения оригинала, которые нужно учитывать

- `excluded` и `itemNames` сопоставляются подстрокой (`CONTAINS`), поэтому «active» совпадает с «Radioactive». В форке для эффектов нужен точный режим (`EXACT`/по словам).
- `testRun` по умолчанию `true` у правил без явного значения (`Parser.parseBoolean(config.testRun, true)`) — новые правила, написанные приложением, должны задавать его явно.
- `ItemProtection` кэширует результат по `serverHandleID` для `Named` и `Known Legendary Mod`; при смене конфига кэш не сбрасывается до перезахода.

## Задача: управление персонажем через таблицу действий (интеграция с приложением)

Цель: все действия персонажа в инвентаре и контейнерах задаются в приложении в одной таблице, а мод их исполняет по кнопке (или автоматически), с очередью, порядком и отчётом. Сейчас они разбросаны по секциям конфига (`scrapConfig`, `transferConfig`, `campAssignConfig`, `lootConfig`, `npcSellConfig`, `buyConfig`, `extractConfig`, `currencyLimitConfig`, `categoryWeightConfig`) и правятся вручную в JSON/в редакторе IOM.

### Таблица действий (веб-интерфейс приложения)

Одна строка — одно действие персонажа. Столбцы:

| Столбец | Значение |
|---|---|
| Персонаж | Аккаунт и имя (`checkAccountName`/`checkCharacterName`) или «все» |
| Действие | `scrap` (разобрать), `consume` (использовать: еда, химия, схемы, книги), `transfer-to` / `transfer-from` (переместить в контейнер и обратно), `drop` (выбросить), `vend` / `display` / `freeze` (`campAssignConfig`), `sell` (NPC), `buy`, `loot`, `lock` (заблокировать), `extract` (выгрузка), `chain-*` (цепочка легендарок, задачи 4–5) |
| Отбор | Тип предмета, название (подстрока/точное), легендарные эффекты по звёздам, звёзды, класс брони, количество, исключения, «только избранное» |
| Условие запуска | Контейнер/меню (`checkContainerName`), лимит предметов (`maxItems`), порог (вес, крышки) |
| Клавиша | `hotkey` (в т. ч. numpad `n0`…`n9`) или «авто» |
| Порядок | Номер в цепочке, зависимость («после»): сортировка действий |
| Режим | `testRun` / боевой; счётчик «проверено в игре» |
| Последний результат | Сколько предметов в очереди, что выполнено, причины пропусков |

Таблица сортируется и фильтруется (Tabulator, как остальные страницы), строки перетаскиваются для задания порядка выполнения. Запись — только по явной кнопке через `iomconfig.save` (бэкап, inode). Каждая строка преобразуется в правило мода; обратное чтение (импорт существующих правил в таблицу) тоже нужно, чтобы не потерять ручные правила.

### Что нужно от мода (форк)

1. **Единый формат действия** (`"actions": [...]` в конфиге или в `inventOmaticPlan.json`) вместо отдельных секций: `{id, type, character, filter, hotkey, order, after, testRun, maxItems}`. Старые секции остаются запасным путём (чтение оригинального формата).
2. **Новые действия, которых нет в оригинале:** `consume` (использовать предмет: еда, лекарства, схемы, книги, журналы; в оригинале `InventOmaticPipboy` имеет правила Drop/Consume — свести с ним), `drop` (выбросить на землю, если API игры позволяет; иначе только `transfer-to`), `lock` (массовая блокировка по отбору).
3. **Исполнение очереди:** мод выполняет действия с одной клавиши по порядку `order`, останавливается при ошибке, не выходит за `maxItems`, учитывает `delay`, не трогает защищённые предметы (задача 2).
4. **Отчёт мод → приложение:** после каждого запуска писать результат (`id` действия, `queued`, `done`, `skipped` с причинами, время, персонаж) в файл рядом с `LegendaryMods.ini` (например `Data/inventOmaticLog.json`, дописывать в конец, ограничить размер). Приложение читает его в `watch`, показывает в таблице («Последний результат») и в «Истории». Способ записи файла выяснить по тому, как мод пишет `LegendaryMods.ini`/выгрузку (`extractConfig`, `Logger`); если запись произвольного файла недоступна, использовать канал `extractConfig.apiMethods`.
5. **Автозапуск (опционально):** `"autoExecute": true` у действия (как у `lootConfig.autoExecute`): запуск при открытии нужного меню/контейнера, без нажатия клавиши. По умолчанию выключен; включается только после успешного `testRun`.
6. **Ограничение клавиш:** одна клавиша может запускать несколько действий (как сейчас у G); для numpad таблица предупреждает о конфликте с другими модами (`docs/mods.md` в `/games/fallout76configs`).

### Что делает приложение

- Страница «Действия» (`/actions`): таблица, сортировка, перетаскивание порядка, фильтры по персонажу и типу, массовые операции (включить/выключить, `testRun`), предпросмотр итогового JSON с diff.
- Таблица БД `actions` (id, персонаж, тип, отбор JSON, клавиша, порядок, режим, enabled, последний результат) и миграция в `db.py`; импорт существующих правил из `inventOmaticStashConfig.json`.
- Генерация правил из таблицы и запись конфига (`iomconfig`), проверка `validate`.
- Чтение отчёта мода (`inventOmaticLog.json`) в `watch`, уведомления («очередь разбора выполнена», «пропущено N защищённых»).
- Интеграция с цепочкой легендарок: действия `chain-*` собираются из `fo76db/legscrap.py`, остальные редактируются вручную.
- Тесты, документация и `CHANGELOG.md` — по правилам `CLAUDE.md`.

Порядок работ: сначала пункты форка 1–2 (эффекты по звёздам и защита), затем формат действий и отчёт (3–4), в приложении — таблица и импорт правил.
