# Редактор правил Invent-O-Matic (`/iom`)

Редактирует конфиг мода Invent-O-Matic Stash — `inventOmaticStashConfig.json`. Путь задаётся ключом `iom_config` в `config.toml`,
по умолчанию `/games/fallout76configs/modconfig/inventOmaticStashConfig.json`. Это **жёсткая ссылка** на `Data/inventOmaticStashConfig.json`
игры, поэтому писать в файл можно только с сохранением inode.

**Это единственное место, где fo76db пишет в файлы игры и пресетов.** Всё остальное утилита только читает.

## Что на странице

- **Вкладки по разделам конфига:** перекладывание, продажа, покупка, разбор, лут, защита, цены в лавке, колонки, выгрузка (Extract) и другие.
  Простые поля показаны формой, списки правил — раскрывающимися карточками; правила можно добавлять, копировать, удалять и переставлять.
  `#<раздел>` в адресе открывает нужную вкладку. Неизвестные ключи сохраняются как есть.
- **Баланс.** Правила вида «держать N в инвентаре» (перекладывание с `exactAmountInDestination`) с превью по последней выгрузке
  персонажа из шапки: что кнопка заберёт из тайника или положит в него. Есть конструктор нового правила «держать N».
- **JSON** — весь файл текстом.
- **Кнопки:**
  - «Проверить»;
  - «Скачать черновик» — файл собирается в браузере, оригинал не трогается;
  - «Перечитать»;
  - «Записать в игру…» — перед записью показывается список изменений (было → стало, до 40 строк), подтверждение — «Записать в игру»;
  - «Откатить к бэкапу…» — выбор из последних 30 бэкапов (по умолчанию самый новый); текущая версия перед откатом тоже уходит в бэкап.

## Проверка (`iomconfig.validate`)

| Уровень | Что проверяется |
|---|---|
| ошибка | `extractConfig.useCustomFormat` включён: fo76db не прочитает такую выгрузку. Неверные типы списков и чисел |
| предупреждение | Extract выключен. Повторяющиеся правила: совпадают все поля, кроме названия, клавиши, `enabled`, `debug`, `showButton`, `testRun`. Повторяющиеся `itemNames` |
| информация | «Живые» правила продажи, покупки и разбора без `testRun`. Одинаковые клавиши у разных правил |

С ошибками файл не сохраняется.

## Порядок записи (`iomconfig.save`)

1. Проверка. Если есть ошибки — отказ.
2. Сверка sha1 с тем, что было при открытии. Если файл изменили снаружи (игра, другой редактор, вторая вкладка) — отказ, файл нужно перечитать.
3. Если ничего не изменилось — запись не выполняется.
4. Копия текущего файла в `<backup_root>/_backup_<ГГГГММДД>/inventOmaticStashConfig.<ЧЧММСС>.json`. По умолчанию `backup_root` — `/games/fallout76configs`.
5. Запись на месте: `open("r+")`, `write`, `truncate`, `fsync`. Тот же отступ, что в оригинале (табуляция), ключи в прежнем порядке.
6. Проверка, что inode и число ссылок не изменились. Если изменились — громкая ошибка.

**«Откатить к бэкапу…»** сохраняет текущий файл в бэкап и тем же способом возвращает выбранный бэкап (в списке первым стоит самый свежий).

**Файл с комментариями `//`** (так выглядит дефолтный конфиг мода в `modconfig/standart/`) — это не строгий JSON. Редактор его не перезаписывает:
без потерь его не сохранить.

## Проверка вручную после первого сохранения

- `ls -li /games/fallout76configs/modconfig/inventOmaticStashConfig.json` — число ссылок по-прежнему 2.
- В игре Invent-O-Matic загружает конфиг без ошибок.

## Правила LegeScrap по персонажам

Страница «Действия» (`/actions`) ведёт правила в таблице и пишет их в те же секции: правила приложения получают поле `fo76db` (id действия), `testRun` задаётся явно; импортированные правила заменяются на месте по хэшу, ручные остаются. Запись — через `iomconfig.save`.

Страница «Защита» может заменить общее правило `LegeScrap` набором правил `LegeScrap <имя>`: у каждого `checkCharacterName`/`characterName` (и `accountName`, если известен), клавиша та же. `excluded` = эффекты, нужные другому персонажу (английские и локальные названия), плюс (по галочке) прежний ручной список. При повторном применении правила `LegeScrap <имя>` заменяются; остальные правила (AutoScrap и др.) не трогаются. Запись — через обычное сохранение редактора (бэкап, inode).
