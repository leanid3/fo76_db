# Данные и правила обработки

## Источники

| Что | Откуда |
|---|---|
| Список предметов, названия EN/RU | `SeventySix.esm` + `SeventySix - Localization.ba2` установленной игры |
| Статы, крафт, разбор, выпадение, Atom Shop | [fwdekker/fo76-dumps](https://github.com/fwdekker/fo76-dumps), последний не-PTS релиз |
| История появления | `tabular.IDs.csv` всех стабильных релизов fo76-dumps (первый — 1.0.5.10, январь 2019) |
| Названия обновлений и даты | [Fallout Wiki: Fallout 76 patches](https://fallout.fandom.com/wiki/Fallout_76_patches) |
| Инвентарь | Invent-O-Matic Stash, функция Extract (клавиша `O` в тайнике или у торговца). Пишет JSON в `Data/itemsmod.ini` |
| Легендарные моды | Improved Workbench (`LegendaryMods.ini`, пишется при входе в режим крафта на верстаке модификатора) |
| Коды ракет | [NukaCrypt](https://nukacrypt.com) |
| Календарь событий, Минерва (расписание и схемы) | [falloutbuilds.com](https://www.falloutbuilds.com/fo76/events/) — HTML-страницы `/fo76/events/` и `/fo76/minerva/` |
| Сезоны, списки Daily Ops | [fallout.wiki](https://fallout.wiki/wiki/Fallout_76_Seasons): `Fallout_76_Seasons`, `Daily_Ops/Variables` |
| Где лежит в мире | `tabular.*_LOC.csv` fo76-dumps (LVLI, WEAP, ARMO, MISC, FLOR) |
| «Как получить» (текст) | Страница предмета на [fallout.fandom.com](https://fallout.fandom.com), запасной — [fallout.wiki](https://fallout.wiki); разделы Locations / Vendors / Obtaining. Русская — [fallout.fandom.com/ru](https://fallout.fandom.com/ru): «Описание», «Местонахождение» |

Пути игры (папка `Data`, ini, конфиг IOM, бэкапы, папка модов) определяются автоматически (`fo76db/gamepaths.py`: Steam на Windows/Linux/Flatpak, Proton, Xbox / Microsoft Store, Bethesda.net) и меняются в «Настройки → Пути игры» (`data/paths.json`). Порядок приоритета: `FO76DB_GAME_DATA` → `data/paths.json` → `config.toml` → автоопределение. Выгрузки (`inventory`, `legendary_mods`) по умолчанию берутся из папки `Data`; дополнительные файлы и шаблоны glob задаются в `config.toml` (см. `config.toml.example`).

## Импорт инвентаря

- **Снимки.** Новый снимок создаётся, только если выгрузка персонажа изменилась (`digest` по инвентарю и тайнику).
- **Категория** вычисляется по битам `filterFlag`. Если флаг равен 0 (надетое, витрины), категория определяется по карточке предмета (`$dmg`, `$ROF` — оружие, `$dr` — броня).
- **Сопоставление с каталогом идёт по названию:** в выгрузке FormID нет.
  - Символы `¢` и `¬` из названия убираются.
  - Из одноимённых записей выбирается подходящая по категории и реально встречающаяся в игре.
  - У оружия и брони с легендарными префиксами базовое название ищется в конце строки.
  - Переименованные игроком вещи не сопоставляются (фильтр «не найдены в каталоге»).
- **Вес.** В инвентаре берётся `weight` с учётом перков. В тайнике — `weightInStash`: игра считает тайник без перков.
  До 2026-10-04 в тайник писался `weight`, и вес тайника был занижен. Старые записи исправлены разовой правкой `fix_stash_weight`.
- **Изученные схемы.** Схемы с `isLearnedRecipe` попадают в `known_recipes` с `source = auto`.

## Изученные схемы

- **Источники отметок.** Полного списка изученных схем игра не выгружает, поэтому их два:
  - `auto` — схема была в инвентаре с пометкой «изучено»;
  - `manual` — отметки на сайте.

  Из крафта изученность не выводится.
- **Предмет считается изученным,** если изучена хотя бы одна схема, которая его даёт (по таблице `recipes`).
- **При снятии отметки** удаляются только ручные; авто-отметки остаются.

## История обновлений

- **Как определяется «добавлено в».** У каждого предмета это первый стабильный релиз fo76-dumps, где появился его FormID.
- **Неточность.** Сборка относится к обновлению по ветке версий, а контент появляется в файлах раньше официального релиза.
- **Старый контент.** Всё, что было в игре до января 2019, помечено как «Базовая игра».

## Как получить (`fo76db/obtain.py`)

- **Списки добычи.** При сборке каталога сохраняется весь граф LVLI: `lvli` (список, EditorID) и `lvli_edges` (что в какой список входит).
  Для предмета поднимаемся по графу до 15 уровней и берём все встреченные списки. Каждый раскладывается по категории правилами `RULES`
  по EditorID (первое совпадение выигрывает): `Minerva`, `GoldVendor_*_Mortimer` и т.п. — торговцы за золото; `DailyOps`, `XPD`, `AC_`,
  `V94_`/`V96_`/`Raid` (но не `Raider`), `Fishing`, `TreasureMap`, `Bounty` — активности; `SCORE_S<N>` — сезон; `ATX_` — Atom Shop; `E<NN>_…`, `Festive`,
  `Spooky`, `MutatedEvents`, `MSilo` и др. — события; `Quest`/`Reward`/`MQ`/`SQ` — квесты; `LLD_`/`LLE_`/`Creature` — враги;
  `Vendor` — торговцы за крышки; `Container`/`Loot`/`Safe`… — контейнеры. Служебные (`zz…`, `DEPRECATED`, `CUT_`, `Debug`, стартовые наборы) пропускаются.
- **Это эвристика.** EditorID — внутренние имена разработчиков: подписи могут быть неточными, шансы и условия (уровень, репутация, Fallout 1st)
  не учитываются. Квестовые награды, которые выдаёт скрипт, ранги сезона и Atom Shop через списки не проходят — для них есть вики.
- **В мире.** Из `*_LOC.csv` по каждой ячейке считается, сколько раз стоит предмет или список добычи (`placements`). Название ячейки —
  из кавычек, а если его нет — из EditorID (`POITrainStationBerkeleySpringsExt` → «Train Station Berkeley Springs»).
  Тестовые и служебные ячейки (`76QA…`, `zCUT…`, `Warehouse…` и т.п.) отбрасываются.
- **Крафт.** Для предмета, который делается по схеме, то же самое считается и для схемы. Минерва — по `minerva_plans` (сам предмет или его схема).
- **Вики.** Две вики по порядку: fallout.fandom.com (полнее, новые предметы появляются быстрее), затем fallout.wiki.
  Обе — через `api.php` (`?action=raw` fandom закрывает): одним запросом `query` по названиям `<имя> (Fallout 76)` и `<имя>`
  (для схем — ещё имя без «Plan: »), с переходом по перенаправлениям. Если не подошло — `opensearch`: он не учитывает регистр
  (у нас «Phantom Outfit», на вики «Phantom outfit»). Страница принимается, если в ней есть FO76 и FormID в инфобоксе (если указан)
  совпадает с предметом. Берутся разделы Location(s), Obtaining, Acquisition, Vendors, Rewards; разметка упрощается до текста и списков,
  всё экранируется; переменные вики (`{{#var:…}}`) заменяются на «?». Кэш — `wiki_obtain`: найденное — 14 дней, «не нашлось» — сутки.
- **Русская вики** (fallout.fandom.com/ru): название страницы берётся из межъязыковой ссылки английской страницы fandom (`prop=langlinks`),
  иначе — `name_ru` из игры (точно, с « (Fallout 76)», затем поиском). В игре кавычки прямые, на вики — «ёлочки»: пробуются оба варианта
  (`Схема: окраска "Свист в темноте"` → `Схема: окраска «Свист в темноте»`). Та же проверка FormID: в русской вики он короткий (`{{ID|8E0691}}`).
  Разделы: Описание, Местонахождение, Получение, Где найти, Торговцы, Награды.
- **Шаблоны в разделах** раскрываются через `api.php?action=expandtemplates` (один запрос на страницу): например, «Местонахождение»
  бывает одним шаблоном `{{LL DailyOps Rewards HighLVL Chase Rare}}`, который разворачивается в текст с шансами по рангам Daily Ops.
  Если раскрыть не удалось, шаблоны выпадают из текста, как раньше.
- **Сеть.** У fallout.wiki несколько IP-адресов, и часть отсюда не отвечает. `sources/net.py` даёт 3 с на подключение к каждому адресу
  и запоминает рабочий — иначе запрос висел 15–30 с.

## Автотеги (`fo76db/autotags.py`)

- **Хранение.** `item_auto_tags(formid, tag)`, код тега — `группа:значение` (`rarity:epic`, `season:26`, `score:5`, `src:Daily Ops`,
  `event:Фаснахт`, `state:new`). Подписи и цвета — в коде (`describe`), в базе только коды.
- **Пересчёт** целиком, ~0,3 с. Ленивый (`ensure`): при первом запросе страницы, если изменились `catalog_release`, `catalog_esm`,
  `history_latest` или `events_fetched` (ключ в `meta.autotags_key`).
- **Редкость** — ключевые слова: `ATX_ItemRarity_Standard/Rare/Superior/Nuclear` (Atom Shop) → Обычное / Редкое / Превосходное / Ядерное;
  `ItemRarity_Low/Medium/High/Epic` → Обычное / Необычное / Редкое / Эпическое. `ATX_ItemRarity_None` пропускается. Цвета выбраны
  по привычной шкале (серый, зелёный, синий, фиолетовый, золотой), в игре их нет.
- **Сезон добавления** — дата сборки `added_build` (дата выхода обновления по вики, если известна, иначе дата выгрузки) попадает в даты
  сезона из `events` (`kind = season`, fallout.wiki). Предметы первой выгрузки (май 2019) — «До сезонов»: точной даты у них нет.
- **Откуда** — те же правила `obtain.classify` по EditorID списков добычи, но только надёжные категории: золото, скрип, Минерва,
  Daily Ops, экспедиции, рейды, Атлантик-Сити, рыбалка, карты сокровищ, Atom Shop (`ATX_`), награды табло (`SCORE_S<N>` → `score:N`),
  сезонные события (`SEASONAL`). Враги, контейнеры, квесты и обычные события (Королева, шахты) в теги не идут — их слишком много,
  они есть в «Как получить». Теги спускаются по графу `lvli_edges` от списка ко всем вложенным, пока множество растёт.
  Плюс Минерва по `minerva_plans`, Fallout 1st по ключевому слову `ATX_Entitlement_Category_Store_Fallout1st`.
  Теги источников схемы копируются на предмет, который по ней крафтится.

## Легендарные эффекты по звёздам (`fo76db/legendary.py`)

- В выгрузке Invent-O-Matic эффекты — одна строка через « / » в порядке звёзд. Части «SET BONUS…» (сетовые бонусы) отбрасываются,
  первые `stars` частей — звёзды, в части берётся первая строка. Остальное (встроенные свойства оружия: «+65% Damage to Scorched»,
  проклятые эффекты, вторые строки) — `leg_extra`.
- Название эффекта — по описанию из `known_legendary_mods` (LegendaryMods.ini) с учётом звезды; хвост «Currently …» и значки `§ ½ ¹`
  отбрасываются, регистр не важен. Русское название — `items.name_ru` легендарного мода. Так определяется ~95% звёзд;
  остальные (сдвинутые порядки, мусорные значения вида `-2.14748e+09% Weapon Speed`) ищутся только по тексту описания.

## Нужные роллы (`fo76db/rolls.py`)

- **Шаблон звезды** сравнивается с эффектом на этой звезде (`legendary.slots`): описание, название EN, название RU, без учёта регистра.
  Подстрока; с `*`/`?` — шаблон (`*` — любые символы); варианты через `|`. Та же логика на фронте — `starMatcher` в `app.js`.
- **Тип хотелки** по категории записи инвентаря: «оружие» — `weapon`, «броня» — `armor` и `apparel`, «любое» — всё.
- **Оценка** — по лучшей хотелке подходящего типа: сначала полное совпадение, потом больше совпавших звёзд, потом меньше заполненных.
  `god` — совпали все заполненные звёзды, `partial` — хотя бы одна, `scrip` — ни одной (но хотелки этого типа есть).
  Звёзды без названия (≈5%, см. ниже) совпадают только по описанию.
- **Уведомления:** ключ совпадения — персонаж плюс ключ предмета (`name|stars|legendary`). При сохранении хотелки все текущие полные совпадения
  записываются в `leg_want_seen` без уведомления. Тот же предмет, переложенный в тайник, не уведомляет повторно; переданный другому
  персонажу — уведомит (это новый ключ).

## Схемы: изучить, передать, продать (`fo76db/plantransfer.py`)

- **Кто знает схему:** `known_recipes` (авто и ручные отметки) плюс пометка «изучено» у самой записи инвентаря.
- **Ученики** — персонажи с данными (есть снимок инвентаря или отметки), кроме отмеченных складом (`profiles.mule`).
- **Действие:** держатель — ученик и не знает → «изучить» (и кому она ещё нужна); иначе есть ученики, которые не знают, → «передать»;
  иначе — «продать». Персонажи без данных не учитываются: у них схема может быть изучена.

## События

- **Обновление** (`fo76db events`, кнопка «Обновить», `watch` раз в 6 ч, после ошибки — через 15 мин): автособытия источника, которые ещё не закончились, заменяются свежими;
  прошедшие остаются историей, ручные не трогаются. Ошибка одного источника не мешает остальным и пишется в `meta.events_error`.
- **Даты.** У источников только дни. Начало и конец события — момент дневного сброса (12:00 по Нью-Йорку) в первый и последний день; в базе — местное время.
  Конец включительно: «Oct 8 – Oct 12» = с 8-го 12:00 ET до 12-го 12:00 ET.
- **Календарь falloutbuilds** — сетка дней (`data-day`), событие = подряд идущие дни с одним названием. Минерва берётся не из календаря,
  а из её таблицы (там точные даты и место). Год у дат Минервы подбирается ближайший к сегодняшнему.
- **Тип события** определяется по названию (`events.kind_of`): Minerva → Минерва; Double…, Sale, Caps-A-Plenty → бонус; Scorched, Fasnacht,
  Meat Week, Mothman, Invaders, Treasure Hunter, Mischief Night, Mutated Public Events, Anniversary, Contest → сезонное событие.
- **Схемы Минервы** сопоставляются с каталогом по `name_en` (без учёта регистра, `’` = `'`). Супер-распродажа (4, 8, 12…) — объединение трёх предыдущих.
  На 2026-10-04 из 479 названий не нашлись 4 (`minerva_plans.formid` = NULL).
- **Сезон** идёт с даты из таблицы вики до начала следующего; у текущего конца нет.
- **Сброс дня и недели** — 12:00 по Нью-Йорку, неделя со вторника (`RESET_*` в `events.py`). Это допущение по данным сообщества; вики пишет «Daily Ops rotate at 1:00pm EST».
  Чек-лист хранит отметки по ключу периода, поэтому после сброса он пустой без всякой очистки.

## Steam (`fo76db/steam.py`, `sources/steam.py`)

- **Источник** — публичные API Steam, ключ не нужен: `ISteamNews/GetNewsForApp` (Update Notes — записи с тегом `patchnotes`, остальное — новости сторонних лент),
  `ISteamUserStats/GetNumberOfCurrentPlayers`. steamdb.info закрыт Cloudflare и не используется.
- **Онлайн** — только игроки Steam. История API не отдаётся: замеры копятся с первого запуска `watch` (раз в 15 минут) и хранятся 400 дней.
- **Достижения** — названия и условия со страницы `steamcommunity.com/stats/1151340/achievements` (русский), редкость и технические имена — `GetGlobalAchievementPercentagesForApp`; обе выдачи отсортированы по проценту и сопоставляются по позиции только если число строк и число строк совпало, а проценты различаются не больше чем на 0,25 (иначе `api_name` пуст). Обновляются раз в сутки. Личный прогресс (`GetPlayerAchievements`) требует Steam Web API key и публичный профиль — не реализован.
- **Тепловая карта** — среднее по `online_samples` для каждого дня недели и часа местного времени; считается готовой при ≥ 7 днях с замерами.
- **Сборка** — `BuildID` из `steamapps/appmanifest_1151340.acf` в найденных библиотеках Steam (`gamepaths.steam_build`, только чтение). Смена BuildID записывается
  событием «Игра обновилась» (`events.source = 'steam'`) и даёт уведомление; первый запуск только запоминает текущую сборку.
- **Уведомления:** о каждой новой заметке к патчу (ключ `steamnews:<gid>`) и о смене сборки (`steambuild:<id>`). Заметки, найденные при первом заполнении таблицы, считаются старыми.

## Ограничения

- **Оценка роллов** не видит уровень предмета, прочность и моды — только эффекты по звёздам.

- **Легендарные моды в русском клиенте.** Improved Workbench пишет свой перевод названий. Около трети из них не сопоставляется с английскими и показывается отдельными строками.
- **Расписание Atom Shop** отложено (позже — uf.atomicshop.fyi).
- **Daily Ops** вносятся вручную: открытого источника ротации нет, nukaknights.com отсюда недоступен.
- **События** зависят от вёрстки falloutbuilds.com и fallout.wiki: при её смене парсер вернёт пусто или ошибку (видно у кнопки «Обновить»).
- **Fallout 1st** (ящики для хлама и патронов) в выгрузке не виден, поэтому в оптимизаторе включается галочкой.
