### Безопасность и сборка (аудит, продолжение)
- CSP: скрипты только свои и инлайн-блоки с одноразовым nonce, `default-src 'self'`, `object-src 'none'`, `base-uri 'none'`, `form-action 'self'`; страницы `/docs` и `/redoc` (Swagger с CDN) без CSP, кроме запрета встраивания. Проверено на всех страницах.
- `requirements.lock`: зависимости с версиями и sha256 (`uv pip compile pyproject.toml --universal --generate-hashes -o requirements.lock`); Docker-образ ставит их через `--require-hashes`.
- Диагностика `watch`, задач, уведомлений и загрузок идёт через `logging` (время, уровень, модуль) вместо `print`; вывод команд CLI не менялся.
- `web/app.py` разделён: защита и вход остались в нём, страницы и API — в `web/routes/` по темам, общее — в `web/common.py`. Маршруты и поведение те же. `docs/openapi.json` обновлён.

### Изменено (надёжность, аудит)
- **БД**: `db.connect()` проверяет схему и миграции один раз на процесс (раньше на каждый запрос), ждёт блокировку до 30 с (`busy_timeout`), `synchronous=NORMAL`; гонка `duplicate column` при одновременном старте `serve` и `watch` обработана. Индексы `known_recipes(formid)`, `events(start)`.
- **Настройки**: `config.load()` кэшируется до изменения `config.toml`, `paths.json`, `network.json` или переменных окружения; `paths.json` и `network.json` пишутся атомарно (временный файл + `os.replace`); испорченный файл попадает в журнал, а не сбрасывается молча.
- **`watch`**: пути перечитываются из настроек без перезапуска; вместо `sleep(2)` ждёт, пока файл перестанет меняться; любая ошибка цикла (исчезнувший файл, права) не останавливает слежение.
- **Загрузки fo76-dumps**: только `https` и хосты GitHub (включая редиректы), до 3 попыток с паузой (5xx, 403/429, обрывы; понятное сообщение при исчерпанном лимите GitHub — поможет `GITHUB_TOKEN`), запись на диск потоком с проверкой размера, `os.replace`, `.part` не остаётся.
- **Запись IOM**: бэкап сбрасывается на диск (`fsync`); если запись в конфиг оборвалась, исходное содержимое возвращается автоматически.

### Добавлено (Flatpak с окном Qt, пакет Arch)
- **Flatpak** теперь открывает десктоп-окно на Qt вместо терминала с сервером и браузером: `fo76db-launch` без аргументов запускает
  `desktop`, ярлык без терминала. В пакет входят PySide6 (после чистки `trim-qt.sh`), `krb5` (нужна `libQt6Network`), доступ к Wayland/X11 и GPU,
  `QTWEBENGINE_DISABLE_SANDBOX=1` (изоляцию даёт Flatpak). Веб-режим: `flatpak run io.github.leanid3.fo76db serve --open`. Бандл ~137 МБ.
  Журнал запуска из меню — `data/desktop.log` (переменная `FO76DB_DESKTOP_LOG=1` включает его и вне exe).
- **Пакет Arch / CachyOS** (`packaging/arch/PKGBUILD`): `makepkg -si` из рабочей копии, окно на системном Qt (`pyside6`, `qt6-webengine`),
  ~2 МБ без своей копии Chromium. Отдельные пакеты под другие дистрибутивы не делаем: для остальных — Flatpak.

### Исправлено (даты событий при русской локали)
- Обновление событий в десктоп-версии (Qt выставляет локаль из окружения) падало: `time data 'Nov 12' does not match format '%b %d'`
  и то же для сезонов и патчей с fallout.wiki. Даты разбираются без `strptime` (`fo76db/sources/dates.py`), заодно 29 февраля.
  Проверено под `ru_RU.UTF-8`: календарь 21 событие, схем Минервы 479, сезонов 26.
- `watch`: после неудачного обновления событий повтор через 15 минут (`RETRY_AFTER_ERROR`), а не через 6 часов. Раньше ошибка в первый
  же запуск оставляла события пустыми до вечера, даже когда причина уже исправлена.

### Исправлено (десктоп Linux)
- Сборка из Actions падала при запуске (`SIGABRT`, `QRhiGles2: Failed to create context`): внутри лежал `libstdc++` с Ubuntu 22.04,
  а системный Mesa на свежих дистрибутивах требует новее (`GLIBCXX_… not found (required by libSPIRV-Tools.so)`) → нет OpenGL.
  `packaging/fo76db-desktop.spec` больше не кладёт в сборку системные библиотеки (`HOST_LIBS`: libstdc++, libgbm, libdrm, GL, X11/xcb,
  glib/GTK, NSS и др.), сборка стала меньше (~456 МБ). Обход для старой сборки — в `docs/packaging.md`.

### Документация
- Flatpak-пакет ссылается на среду через `dl.flathub.org` (CDN) вместо `flathub.org`, который бывает недоступен (таймаут при установке);
  обход для старых пакетов — `--no-deps`.
- Установка Flatpak: `flatpak install --user --bundle ...`, артефакт Actions сначала распаковать из zip; разбор ошибки
  «не является корректным именем» (файл не найден — flatpak ищет во Flathub).

### Исправлено (сборка Windows)
- GitHub Actions на Windows: `packaging/third_party.py` падал с `UnicodeEncodeError` (cp1252) на кириллице в выводе — задачи
  `desktop` и `binary`. Скрипт переключает вывод на UTF-8, а workflow задаёт `PYTHONUTF8=1` для всех шагов.

### Добавлено (десктоп, PWA, данные из интерфейса)
- **Десктоп-версия** — веб-интерфейс в своём окне (`fo76db/desktop.py`, команда `fo76db desktop`, extra `[desktop]`, pywebview):
  Linux — Qt WebEngine (PySide6), сборка-папка `fo76db-desktop-linux-x86_64.tar.gz` с `install-linux.sh` для ярлыка;
  Windows — Edge WebView2, один файл `fo76db-desktop-windows-x86_64.exe` без консоли. Сервер и слежение за выгрузками внутри,
  при уже запущенном сервере окно открывается на нём. Spec — `packaging/fo76db-desktop.spec`, задача `desktop` в Actions.
- **PWA** ([docs/pwa.md](docs/pwa.md)): манифест, service worker (сначала сеть, без связи — последняя копия страниц и API),
