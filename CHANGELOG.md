## 2026.10.9 (2026-10-09)

### Добавлено (2026-10-09, версии мода)
- Версии в лаунчере: мод в Data, оригинал в бэкапе и версия, под которую написан форк (читаются из класса `Version` в swf через ffdec, кэш `data/launcher/versions.json`). Чистый архив нового мода в Data (после обновления с Nexus) принимается как новый оригинал; при несовпадении версий сборка останавливается (`build --force` / «Собрать (force)» — осознанно).

### Добавлено (2026-10-09, развёртывание)
- «Развернуть одной кнопкой» (`/launcher`, `fo76db launcher deploy --yes`): сборка форка → архив мода в Data → включение форка → запись правил в конфиг IOM → запись плана цепочки; каждый шаг с бэкапом, результат по шагам. Исходники форка берутся из `mod_fork_dir`, затем из `mod-fork/` рядом с приложением, затем из `~/src/Invent-O-Matic-Stash-modificaed`. Оригинал архива мода без бэкапа берётся из текущего Data и копируется в бэкап.

### Изменено (2026-10-09)
- При включённом форке мода страница «Защита» оставляет только список защищённых предметов; запись правил LegeScrap отключена (`/api/legscrap/*` отвечает 409), правила разбора и передачи ведёт «Действия» (`chain-scrap`, `chain-give`, `chain-take`).

### Добавлено (2026-10-09, лаунчер)
- Лаунчер: страница `/launcher` и команда `fo76db launcher status|build|install|rollback|units|start|stop|restart|export|import` (`fo76db/launcher.py`). Диагностика «почему форк мода не работает» (архив в Data, `modFork`/`markConfig` в конфиге, план цепочки, инструменты сборки, `serve`), сборка форка из исходников (ffdec + `tools/ba2.py`, результат в `data/launcher`; при тех же исходниках sha1 совпадает с установленным), установка и откат `InventOmaticStash-UO.ba2` в Data (бэкап в `_backup_<дата>/Data/`, только локально и с подтверждением), юниты systemd `--user` для `serve`/`watch`, перенос базы и настроек одним архивом. Параметр `mod_fork_dir` в `config.toml`.

### Добавлено (дополнение)
- Список уникальных предметов сверен с официальным патчноутом The Slasher (Unique Item Crafting, 83 предмета), вики и скриншотами списков (каталог uniquelegend): добавлены недостающие (всего 120), источник `manual`; V63 Zweihaender убран (в патче 70 стал обычным оружием).

### Исправлено
- Выученные моды персонажей с одинаковым именем («main» у RedTiger936 и nikso_olumb): `LegendaryMods.ini` не содержит аккаунта, и файл RedTiger936 считался устаревшим данными nikso_olumb. Аккаунт теперь берётся из `itemsmod.ini` в той же папке выгрузки.
- Правила LegeScrap не учитывают `scrapProtection.itemNames` (проверено тестовым прогоном `testRun` в игре: защищённые предметы попали в очередь). Названия защищённых предметов теперь дописываются и в `excluded` каждого правила LegeScrap.

### Добавлено (действия)
- Страница «Действия» (`/actions`, таблица `actions`, `fo76db/actions.py`): правила мода Invent-O-Matic как строки таблицы — тип, персонаж/аккаунт, клавиша, отбор (JSON), порядок (перетаскивание, зависимость «после»), `testRun`, вкл/выкл, массовые операции. «Импорт из конфига» добавляет правила игры (повторно не дублирует, неизвестные поля сохраняются), «Предпросмотр» показывает diff и проверку `validate`, «Записать» — через `iomconfig.save` (бэкап, inode; только с этого компьютера, с подтверждением). Ручные правила запись не трогает. Типы `consume`, `drop`, `lock`, `chain-*` и эффекты по звёздам в scrap хранятся в таблице, но пишутся в конфиг только при `modFork.version` ≥ 1 (форк мода). Тесты `tests/test_actions.py`.

### Добавлено (форк: цепочка, годролы, метки)
- «Действия»: переключатель «Установлен форк мода»; при нём в конфиг пишутся `modFork`, `markConfig` (цвет, подпись и включение меток годролов, уникальных и «нужен другому»), `godrolls[]` (шаблоны звёзд 1–3 раскрыты в точные названия эффектов) и `uniqueNames[]` в `scrapProtection`/`transferProtection`, а типы `chain-scrap`/`chain-give`/`chain-take` становятся правилами `mode: chain*`.
- План цепочки для мода: «План цепочки…» показывает и по подтверждению пишет `Data/inventOmaticPlan.json` (`fo76db/chainplan.py`): персонажи с приоритетами и назначенный на каждый эффект (бэкап прежнего файла, inode сохраняется — `iomconfig.save_aux`).
- `docs/mod-fork.md` и `BUILD.md` форка описывают формат; в форке — `tools/ba2.py` (распаковка и упаковка BA2).

### Добавлено
- `docs/mod-fork.md`: спецификация форка мода Invent-O-Matic Stash (задачи для форка, контракт полей, что делает приложение при переходе). Копия лежит в форке как `CLAUDE.md`.
- Разбор легендарок по приоритету персонажей (`fo76db/legscrap.py`). Эффект (мод + звезда), который не выучил кто-то из персонажей, достаётся невыучившему с наименьшим приоритетом; остальные такой предмет не разбирают, а передают. Приоритет — `profiles.priority` (0 — высший, по умолчанию 100; leanid2 = 0), задаётся в «Настройки → Персонажи и теги».
- «Вес»: новые советы `leg_give` (передать персонажу), `leg_self` (разобрать самому и выучить), `leg_learned` (все моды выучены всеми: разобрать или на скрип). Защищённые предметы советов не получают.
- Страница «Защита» (`/protected`, таблица `protected_items`): уникальные именные предметы (импорт с fallout.fandom.com), годролы (предмет с 3★+, где звёзды 1–3 «хорошие» по типу и звезде; 4★ не в счёт; стартовый набор, эффекты из избранного, ручной ввод), список предметов под защитой в инвентаре.
- Правила LegeScrap по персонажам: предпросмотр (`/api/legscrap/preview`) и запись в `inventOmaticStashConfig.json` (`/api/legscrap/apply`, бэкап и inode — штатно через `iomconfig.save`). У каждого персонажа своё правило на той же клавише (`checkCharacterName`), исключения = эффекты, нужные другому, плюс прежний ручной список. Тесты `tests/test_legscrap.py`.
- Защита годролов и уникальных в игре: «Записать в конфиг» добавляет их названия в `protectionConfig.scrapProtection.itemNames` (прежние сгенерированные имена заменяются, ручные остаются; совпадения с обычными предметами показываются в предпросмотре). Прежний ручной список исключений LegeScrap теперь по галочке, по умолчанию он отбрасывается. Годролл — предмет минимум с 3★, где звёзды 1–3 «хорошие» (4★ не в счёт).
- Уведомления в Telegram (`telegram_token`, `telegram_chat_id`; сервис «telegram» выключается в настройках), `fo76db notify --test` (проверка каналов) и `--telegram-chat` (узнать chat id).
- Уведомления на телефон через ntfy (`ntfy_topic`, `ntfy_server` в `config.toml`; сервис «ntfy» можно выключить в «Настройки → Разделы и сервисы»). Новый тип уведомления «Годролл без защиты»: в инвентаре появился годролл или уникальный предмет, который не в избранном, не заблокирован и не защищён по названию.

### Безопасность (по результатам CodeQL)

- Действия сторонних авторов в `build.yml` закреплены на SHA коммитов (с комментарием версии; Dependabot обновляет SHA сам).
- Сайт на GitHub Pages: лендинг `packaging/pages/site/` (возможности, скриншоты, таблица загрузок с версией и размерами из GitHub API, быстрый старт) в корне, документация MkDocs — в `/docs/`; включён workflow `pages.yml` (был `pages.yml_back`), раннер `ubuntu-24.04`, кэш pip; `mkdocs.yml`: русские якоря заголовков, `api.md` в навигации, ссылка «О программе».

### Безопасность и сборка (аудит, продолжение)
- CSP: скрипты только свои и инлайн-блоки с одноразовым nonce, `default-src 'self'`, `object-src 'none'`, `base-uri 'none'`, `form-action 'self'`; страницы `/docs` и `/redoc` (Swagger с CDN) без CSP, кроме запрета встраивания. Проверено на всех страницах.
- `requirements.lock`: зависимости с версиями и sha256 (`uv pip compile pyproject.toml --universal --generate-hashes -o requirements.lock`); Docker-образ ставит их через `--require-hashes`.
- Диагностика `watch`, задач, уведомлений и загрузок идёт через `logging` (время, уровень, модуль) вместо `print`; вывод команд CLI не менялся.
- `web/app.py` разделён: защита и вход остались в нём, страницы и API — в `web/routes/` по темам, общее — в `web/common.py`. Маршруты и поведение те же. `docs/openapi.json` обновлён.

  на скрип (ни одной). Оценка — колонка «Ролл» и фильтр в «Инвентаре», совет «на скрип» на странице «Вес». Кнопка «★ В нужные роллы»
  в «Инвентаре» сохраняет текущие поля звёзд как хотелку.
- **Уведомления о нужных роллах:** когда в новой выгрузке появляется предмет с полным совпадением хотелки (с 🔔), приходит уведомление —
  сразу после импорта (`watch`, `fo76db import`) и в общей проверке. О том, что уже было при сохранении хотелки, не уведомляет.
- **Схемы → «Передать и продать»:** для каждой схемы в инвентаре и тайниках — изучить самому, передать (кому именно) или продать (знают все).
